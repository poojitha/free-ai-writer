# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

"Write" — a desktop writing app built with **Wails v2** (Go backend + React/Vite frontend). The user writes in a TinyMCE rich-text editor; an "Improve" panel sends the plain text to a **local Ollama** server and shows the rewritten result. The Go module and binary are named `chromebox` (see `go.mod`, `wails.json`), though the window title is "Write".

## Commands

Run from the repo root unless noted (requires the Wails CLI, Go 1.26, Node):

- `wails dev` — run the app with hot reload (starts Vite via `npm run dev`; also serves a browser dev URL with Go bindings).
- `wails build` — production build; output goes to `build/bin/`.
- `wails generate module` — regenerate `frontend/wailsjs/` bindings after changing exported methods on `App`.
- `cd frontend && npm install` — installs deps; its `postinstall` script (`scripts/copyTinymce.mjs`) copies `node_modules/tinymce` into `public/tinymce`. If the editor fails to load, rerun this.
- `cd frontend && npm run build` — frontend-only build into `frontend/dist`.

There are no tests or linters configured.

## Architecture

- **`main.go`** — configures the Wails window, embeds `frontend/dist` via `//go:embed`, and binds the `App` struct so its exported methods are callable from JS. `frontend/dist` must exist for `go build` to compile.
- **`app.go`** — all backend logic:
  - `startup` resizes/centers the window to 90% of the primary screen.
  - `ImproveText(text, host, model, prompt)` POSTs to `{host}/api/generate` (non-streaming) and returns the trimmed response. Empty args fall back to the `default*` constants.
  - `GetDefaultOllamaSettings()` exposes those defaults so the frontend doesn't duplicate them — the Go constants are the single source of truth.
  - `OpenDocument()` / `SaveDocument(path, content)` read and write the editor's HTML via native file dialogs (an empty path on save prompts for one).
- **`frontend/wailsjs/`** — auto-generated by Wails; don't edit by hand. The frontend imports Go methods from `../wailsjs/go/main/App`.
- **`frontend/src/App.jsx`** — the whole UI: a top bar (theme toggle, save, open, settings), a centered TinyMCE editor in **inline mode** (self-hosted, loaded from `/tinymce/tinymce.min.js`, `licenseKey="gpl"`, no toolbar — formatting via the `quickbars` selection toolbar), and a bottom "AI-Powered Suggestions" panel. Each suggestion chip (`ACTIONS`) sends the selection — or the caret's paragraph — to `ImproveText` with its own prompt; pressing Enter does the same for the line just written using the user's prompt from Settings. Results appear as cards whose **Replace** swaps the text back in using a live DOM `Range` saved at request time (marked stale if that text has since changed). Text is sent as plain text, so formatting is not preserved through the round-trip. Ollama settings (host/model/Enter prompt, plus per-action prompts) are edited in a Settings dialog and persist in `localStorage` under `ollamaSettings`. Default action prompts live in Go (`defaultActionPrompts` in `app.go`, keyed by the `ACTIONS` ids); only the user's edits are stored, under `actionPrompts`. Adding an action means adding both the `ACTIONS` entry and its Go default.
- **Theming** — `frontend/src/theme.js` sets `data-theme="light|dark"` on `<html>` from the user's choice (`system`/`light`/`dark`, stored under `theme`) and swaps the TinyMCE `oxide`/`oxide-dark` skin stylesheets itself (the editor is initialised with `skin: false`). All colours are CSS custom properties in `App.css` with a `[data-theme='dark']` override — add new colours as tokens in both blocks. Fonts (Inter, Source Serif 4) are bundled via `@fontsource-variable`, so the app works offline.
