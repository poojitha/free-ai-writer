# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

"Hush Writer" — a desktop writing app built with **Wails v2** (Go backend + React/Vite frontend). The user writes in a TinyMCE rich-text editor; an "Improve" panel sends the plain text to an AI provider — a **local Ollama** server (the default), **OpenAI** (ChatGPT, or any OpenAI-compatible server) or **Anthropic** (Claude) or any other OpenAI-compatible API ("Other") — and shows the rewritten result. The Go module is `hushwriter` (`go.mod`) and the binary `hush-writer` (`wails.json`); the window title is "Hush Writer".

## Commands

Run from the repo root unless noted (requires the Wails CLI, Go 1.26, Node):

- `wails dev` — run the app with hot reload (starts Vite via `npm run dev`; also serves a browser dev URL with Go bindings).
- `wails build` — production build; output goes to `build/bin/`.
- `wails generate module` — regenerate `frontend/wailsjs/` bindings after changing exported methods on `App`.
- `cd frontend && npm install` — installs deps; its `postinstall` script (`scripts/copyTinymce.mjs`) copies `node_modules/tinymce` into `public/tinymce`. If the editor fails to load, rerun this.
- `cd frontend && npm run build` — frontend-only build into `frontend/dist`.

Tests (no linters are configured):

- `go test ./...` — backend tests in `app_test.go`. `ImproveText` is tested against `httptest` fakes of each provider; a test also checks that the `PROVIDERS` ids in `frontend/src/settings.js` match the keys of `providers`.
- `cd frontend && npm test` — Vitest + jsdom + Testing Library (`npm run test:watch` to watch). Tests sit next to the code as `*.test.js(x)`; `src/test/setup.js` clears `localStorage` between tests. Editor helpers are tested with a small fake TinyMCE editor (see `editorText.test.js`); components mock `../wailsjs/go/main/App` with `vi.mock`.

## Architecture

- **`main.go`** — configures the Wails window, embeds `frontend/dist` via `//go:embed`, and binds the `App` struct so its exported methods are callable from JS. `frontend/dist` must exist for `go build` to compile.
- **`app.go`** — all backend logic:
  - `startup` resizes/centers the window to 90% of the primary screen.
  - `ImproveText(text, prompt, AIConfig{provider, host, model, apiKey})` looks up the provider, prepends the prompt to the text, sends it (non-streaming) and returns the cleaned-up reply. The prompt is required (the frontend always sends one); empty config fields fall back to the provider's defaults; OpenAI/Anthropic require an API key.
  - `GetDefaultSettings()` exposes each provider's default host/model so the frontend doesn't duplicate them — Go is their single source of truth. Prompts are not here; they live in the frontend.
- **`ai.go`** — the providers map (`ollama` → `/api/generate`, `openai` → `{host}/chat/completions` with a Bearer key, `anthropic` → `{host}/v1/messages` with `x-api-key`, `custom` ("Other") → an OpenAI-compatible `{host}/chat/completions` with an optional key and no defaults, so the user must give host and model), their defaults, and the shared `postJSON` helper. Adding a provider means a `providers` entry here plus a `PROVIDERS` entry in `settings.js`.
  - Files: `OpenDocument()` shows an open dialog and returns the file's raw bytes; `ChooseSavePath(currentPath)` shows a save dialog offering Word (`.docx`, the default — listed first so Windows uses its extension), plain text and HTML, adding `.docx` if no supported extension was given; `WriteDocument(path, data)` writes bytes. Go never converts formats — the frontend does. `[]byte` crosses the Wails bridge as a base64 string in both directions (the generated TS types say `number[]`, but pass base64).
- **`frontend/wailsjs/`** — auto-generated by Wails; don't edit by hand. The frontend imports Go methods from `../wailsjs/go/main/App`.
- **`frontend/src/editorText.js`** — the editor-text logic, kept out of components so it can be unit tested: which text an action targets (`getActionTarget`, `getLineBeforeCaret`), where a result goes back (`findReplaceRange`, `widenToBlock`), and `textToHtml`.
- **`frontend/src/documentFormats.js`** — converts editor HTML to/from `.docx` (via the `docx` package; headings, bold/italic/underline/strike, lists with restarting numbering, links, quotes, alignment, and embedded PNG/JPEG/GIF/BMP images sized from their attributes or file header and capped at the page width), `.txt` and `.html` (saved as a full UTF-8 page), choosing by extension. `docx` and `mammoth` (used to open `.docx`) are dynamically imported so they stay out of the startup bundle. Opening a `.docx` loses alignment and quote styling — mammoth doesn't map them. `.txt` drops images; images linked by URL (not embedded) are left out of `.docx`.
- **`frontend/src/settings.js`** — the `ACTIONS` list (each with its default `prompt`; `DEFAULT_PROMPTS` regroups them in the stored shape), the `PROVIDERS` list, persisted settings (`loadStoredSettings`, `toStoredSettings`, `providerFields`, `activeAIConfig`, `resolveActionPrompt`) and the suggestion-height clamp. **`frontend/src/SettingsDialog.jsx`** is the Settings dialog.
- **`frontend/src/App.jsx`** — the rest of the UI: a top bar (formatting-toolbar toggle, theme toggle, save — Shift+click or Ctrl+Shift+S for Save As — open, settings), a centered TinyMCE editor in **inline mode** (self-hosted, loaded from `/tinymce/tinymce.min.js`, `licenseKey="gpl"`, its toolbar is rendered into `#editor-toolbar` inside the top bar via `fixed_toolbar_container` + `toolbar_persist`, includes an image button — the `image` plugin, with `images_upload_handler` turning uploaded/pasted/dropped images into `data:` URLs so they're embedded in the document, limited to the types Word can embed; an `OpenWindow` handler opens the dialog on its Upload tab for new images — hidden on every launch until the pen button toggles it (deliberately not remembered), and restyled with the theme tokens in `App.css`), and a bottom "AI-Powered Suggestions" panel. Each suggestion chip (`ACTIONS`) sends the selection — or the caret's paragraph — to `ImproveText` with its own prompt; pressing Enter does the same for the line just written using the user's prompt from Settings. Results stack as cards (newest first) in a scrollable list; the list grows with its content up to a max height, which the drag handle on the AI bar's top edge sets (stored under `suggestionHeight`). A card's **Replace** swaps the text back in using a live DOM `Range` saved at request time (marked stale if that text has since changed). Text is sent as plain text, so formatting is not preserved through the round-trip. AI settings (the chosen `provider`, a `providers` map of each one's host/model/apiKey, the Enter prompt and per-action prompts) are edited in a Settings dialog (provider chosen from a dropdown) and persist in `localStorage` under `ollamaSettings` only when its **Save** button is clicked — closing discards unsaved edits, while the theme applies immediately (name kept for compatibility; older settings with top-level `host`/`model` are read as Ollama's). API keys are stored there in plain text. Default prompts live in the frontend, on each `ACTIONS` entry in `settings.js`; only the user's edits are stored, under `actionPrompts` (and `prompt`). The `improve` action's prompt is also the Enter-key prompt, stored as `prompt`. Adding an action means adding only an `ACTIONS` entry with its `prompt`.
- **Theming** — `frontend/src/theme.js` sets `data-theme="light|dark"` on `<html>` from the user's choice (`system`/`light`/`dark`, stored under `theme`) and swaps the TinyMCE `oxide`/`oxide-dark` skin stylesheets itself (the editor is initialised with `skin: false`). All colours are CSS custom properties in `App.css` with a `[data-theme='dark']` override — add new colours as tokens in both blocks. Fonts (Inter, Source Serif 4) are bundled via `@fontsource-variable`, so the app works offline.
